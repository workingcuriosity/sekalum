Step 1

Provider details

Create a declarative provider definition. It contains metadata only and never secrets or executable configuration.

Lowercase letters, numbers, and hyphens. This ID cannot be changed after creation.

Supported boundaries

Custom providers support declarative metadata, credential methods, credential fields, method bindings, and display metadata.

OAuth, provider-configuration fields, runtime operations, code, hooks, scripts, and provider-definition secrets are not supported and are rejected.

Step 2

Credential methods

Add at least one method. Each method is selectable in the Credential Wizard after this provider is saved.

Step 3

Credential fields and method bindings

Add the fields that an administrator enters for each credential method. Mark sensitive values as secrets; secrets belong to credentials, not this provider definition.

Step 4

Review and create

Review the declarative definition before it is saved. The new provider becomes selectable in the Credential Wizard immediately after a successful response.
